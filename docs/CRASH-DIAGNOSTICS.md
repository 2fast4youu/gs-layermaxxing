# Local Android crash diagnostics

In **Mehr → Fehlerbericht / Log kopieren**, read the selectable, scrollable report and tap **Log kopieren**. A confirmation appears. Paste it manually where you want to send it. The app never uploads diagnostics or copies them automatically. **Gespeichertes Log löschen** removes the private saved report/events; the clipboard remains under Android/user control.

After a recorded Java crash, the next launch offers a dismissible report prompt before composing session, account, biometric, network or island content. **Später** retains the report and persists dismissal across launches/rotation. A new report prompts again. **Log kopieren** explicitly copies directly from the prompt; **Fehlerbericht ansehen** opens the same preview and copy action. Closing it continues normal startup. No island needs to be reopened. A fresh installation says that no Java crash was recorded, without claiming that the device is healthy.

The Application installs one uncaught handler and preserves the previous one. Report failures still delegate and terminate normally. Private files contain one atomically replaced crash (48 KiB cap), a 32-event current-run snapshot, and a dismissal fingerprint. At most 128 event snapshots are written per process; later events remain bounded in memory for Java-crash capture. New launches retain one bounded previous-run breadcrumb snapshot before resetting current-run events, even when a native/system/low-memory kill bypassed the Java handler. The last Java crash remains until clear or replacement; explicit clear also removes previous-run events. No extra permission or telemetry dependency is used.

Reports include UTC, version/code/build type, API/model, JVM/native heap and process PSS, bounded exception/cause classes and technical app/framework stack frames. Exception messages, thread names, stack filenames/paths, system descriptions/traces and arbitrary event strings are excluded. Breadcrumb callers supply only startup, tab/view enums, friend/message counts and grid version. The host records island entry before child composition; subsequent view changes omit peer IDs. No session/account/letter data is read by diagnostics.

Java handlers cannot capture all native crashes, ANRs, low-memory/process kills, force stops or power loss. On Android 11+, explicitly opening the preview queries this package's last five system exits, showing only UTC, numeric reason code and PSS/RSS. Older Android says that history is unavailable. Missing entries or history API errors do not imply that no crash occurred. Disk-full/OOM recording is best effort; OOM uses prebuilt startup metadata with unknown memory, no stack/event traversal and an explicit timestamp limitation. Storage/atomic rename/fsync can still fail or be interrupted. Release minification can obscure stack names; retain the matching mapping with delivered builds.

Synthetic regressions are named `CrashDiagnostics*Test`: formatter privacy/bounds/cycles, private storage persistence/rotation/clear/write failure, handler failure/recursion/delegation, manifest Application startup, old Android history fallback, actual Compose startup gate, Mehr entry, preview/copy/confirmation/clear/close, and the shared pre-render island boundary. Android compilation and execution belong to Root. Set **CRASH_LOG_SHOTS** to an authorized scratch directory to opt into a native Robolectric `View.draw` PNG labelled synthetic, not a real phone crash. There is no production crash trigger.
